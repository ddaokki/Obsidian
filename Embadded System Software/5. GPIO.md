## 1. GPIO 개요 (Slide 3)
**GPIO**는 '범용 입출력'의 약자로, 마이크로프로세서가 주변 장치와 데이터를 주고받기 위해 사용하는 가장 기본적인 인터페이스입니다.
- **구조:** 각 GPIO는 특정 핀(Pin)에 연결된 **1비트(bit)** 데이터를 나타냅니다.
- **작동 원리:** 전압을 두 가지 레벨(High/Low)로 유지하여 논리적인 **0 또는 1**을 표현합니다.
- **제어:** 한쪽 칩에서 전압을 조절(Control)하면, 연결된 다른 쪽 칩에서 이를 감지(Sense)하여 소통합니다.

---
## 2. 핀 번호 체계 (Pin Numbering) (Slide 4)
라즈베리 파이와 같은 보드에서 핀을 지칭하는 방식은 여러 가지가 있어 주의가 필요합니다.
- **Physical Number:** 보드에 있는 물리적인 핀 순서 (1, 2, 3...)
- **BCM (Broadcom) Number:** CPU(브로드컴 칩) 내부의 채널 번호 (GPIO 17, 27...)
- **WiringPi Number:** WiringPi 라이브러리에서 사용하는 고유 번호 (wPi 0, 1...)

---
## 3. 리눅스 커널의 GPIO 인터페이스 (Slide 5-7)
리눅스 커널은 하드웨어에 의존하지 않고 공통된 방식으로 GPIO를 제어할 수 있도록 표준 함수들을 제공합니다. (`<linux/gpio.h>` 헤더 포함 필요)
### 3.1 사용 전후 처리
- **`gpio_request(unsigned gpio, const char *label)`:** 특정 GPIO 핀을 사용하겠다고 커널에 요청합니다. 다른 드라이버와의 충돌을 방지합니다.
- **`gpio_free(unsigned gpio)`:** 사용이 끝난 핀을 커널에 반납합니다.
### 3.2 방향 설정 (Direction)
GPIO는 입력 또는 출력 중 하나로 설정해야 합니다.
- **`gpio_direction_input(unsigned gpio)`:** 핀을 입력 모드로 설정합니다.
- **`gpio_direction_output(unsigned gpio, int value)`:** 핀을 출력 모드로 설정하며, 초기 출력값(`value`)을 지정합니다.

---
## 4. 데이터 읽기 및 쓰기 (Slide 8-9)
방향 설정이 완료되면 실제 데이터를 주고받을 수 있습니다.
- **`gpio_get_value(unsigned gpio)`:** 해당 핀의 현재 논리 상태(0 또는 1)를 읽어옵니다.
- **`gpio_set_value(unsigned gpio, int value)`:** 출력 모드인 핀에 논리 값(0 또는 1)을 내보냅니다.
- **`gpio_to_irq(unsigned gpio)`:** 특정 GPIO 핀을 인터럽트(IRQ) 번호로 변환합니다. 이를 통해 버튼이 눌렸을 때 특정 함수가 실행되도록 하는 '인터럽트 방식' 제어가 가능해집니다.

---
## 5. 커널 내부의 GPIO 관리 구조 (Slide 10)
커널은 시스템의 모든 GPIO 정보를 **`gpio_desc`**라는 구조체 배열로 관리합니다.
- **구성:** 각 핀의 상태(사용 중 여부, 방향, 현재 값, 레이블 등)를 저장합니다.
- **접근 방식:** 드라이버 개발자는 `gpio_desc`에 직접 접근하기보다는 위에서 설명한 `gpio_get/set_value` 같은 표준 API 함수를 통해 간접적으로 제어하는 것이 원칙입니다.

## 6. WiringPi 라이브러리 (Slide 12-14)
WiringPi는 라즈베리 파이의 GPIO를 아두이노 스타일로 쉽게 제어할 수 있도록 만든 C 언어 라이브러리입니다.
### 6.1 초기화 및 설정
- **`wiringPiSetup()`**: WiringPi 고유 번호 체계를 사용하기 위해 필수적으로 호출해야 합니다.
- **`pinMode(int pin, int mode)`**: 특정 핀을 `INPUT`, `OUTPUT`, 또는 `PWM_OUTPUT`으로 설정합니다.
### 6.2 데이터 입출력
- **`digitalWrite(int pin, int value)`**: 출력 핀에 `HIGH`(1) 또는 `LOW`(0) 전압을 보냅니다.
- **`digitalRead(int pin)`**: 입력 핀의 상태를 읽어 `HIGH` 또는 `LOW`를 반환합니다.
- **`delay(unsigned int howLong)`**: 밀리초(ms) 단위로 실행을 일시 중지합니다.

---
## 7. 다이내믹 타이머 (Dynamic Timers) 개요 (Slide 15-16)
커널 타이머는 미래의 특정 시점에 함수를 실행하도록 예약하는 기능입니다.
- **특징:** 한 번 실행된 후에는 스스로 파괴되는 '일회성'입니다.
- **Context:** 타이머에 등록된 핸들러 함수는 **인터럽트 컨텍스트**에서 실행됩니다. 따라서 핸들러 내부에서는 잠들거나(sleep) 블로킹 연산을 수행하면 안 됩니다.

---
## 8. 타이머 구조체: `struct timer_list` (Slide 17)
타이머를 관리하기 위해 커널은 `timer_list` 구조체를 사용합니다.
- **`expires`**: 타이머가 만료될 절대 시점(jiffies 단위)을 의미합니다.
- **`function`**: 타이머 만료 시 호출될 콜백 함수(핸들러)의 포인터입니다.
- **`data`**: 핸들러 함수에 전달할 사용자 데이터입니다. (최신 커널 버전에서는 핸들러의 인자 구조가 다를 수 있습니다.)

---
## 9. 타이머 주요 함수 (Slide 18)
타이머를 조작하기 위한 핵심 인터페이스들입니다.
- **`init_timer(struct timer_list *timer)`**: 타이머 구조체를 사용하기 전에 기본 상태로 초기화합니다.
- **`add_timer(struct timer_list *timer)`**: 설정을 마친 타이머를 커널의 타이머 관리 목록에 등록하고 활성화합니다.
- **`mod_timer(struct timer_list *timer, unsigned long expires)`**: 이미 등록된 타이머의 만료 시간을 변경할 때 사용합니다. 타이머가 비활성 상태였다면 새로 활성화합니다.

---
**💡 핵심 요약** 12~18페이지는 **사용자 영역에서 GPIO를 쉽게 쓰는 법(WiringPi)**과 **커널이 미래의 작업을 예약하는 법(Dynamic Timer)**을 설명합니다. 특히 **타이머 핸들러는 인터럽트와 같은 환경에서 돌아가므로 매우 빠르고 간결하게 작성해야 함**을 기억하는 것이 중요합니다.

## 10. 타이머 삭제 및 해제 (Slide 19)
활성화된 타이머를 중단시키거나 사용이 끝난 타이머를 정리할 때 사용하는 함수들입니다. 최신 커널 버전에서는 이름이 변경되었으므로 함께 알아두어야 합니다.
- **`del_timer(struct timer_list *timer)`**:
    - 타이머를 비활성화합니다. 활성 상태든 비활성 상태든 상관없이 동작합니다.
- **`del_timer_sync(struct timer_list *timer)`**:
    - **SMP(멀티코어)** 시스템에서 매우 중요합니다. 타이머를 비활성화할 뿐만 아니라, 다른 CPU에서 해당 타이머의 핸들러가 실행 중이라면 **종료될 때까지 기다립니다.**
    - 핸들러가 공유 자원을 사용 중일 때 안전하게 삭제하기 위해 필수적입니다.
- **최신 버전:** 최근 리눅스 커널에서는 각각 `timer_delete()`와 `timer_delete_sync()`로 이름이 바뀌어 사용되기도 합니다.

---
## 11. 타이머 핸들러의 실행 환경 (Slide 21)
타이머가 만료되었을 때 실행되는 함수(핸들러)는 아주 특수한 환경에서 돌아갑니다.
- **실행 메커니즘**: `TIMER_SOFTIRQ`라는 소프트웨어 인터럽트에 의해 실행됩니다.
- **정밀도**: 타이머는 시스템의 **HZ(Tick)** 주기 단위로 체크되므로, HZ보다 더 미세한 단위(예: 나노초)로 정확한 타임아웃을 제어하는 것은 어렵습니다.

---
## 12. 컨텍스트와 지연 함수의 관계 (Slide 22)
이 페이지는 이번 강의의 가장 중요한 요약 중 하나입니다. 어떤 함수를 어느 상황에서 써야 하는지 결정하는 기준입니다.
### 12.1 수면 대기 (Sleep-wait)
- **함수**: `msleep()`, `schedule_timeout()`, `wait_event_timeout()`
- **사용처**: **프로세스 컨텍스트(Process Context)**에서만 사용 가능합니다.
- **주의**: 인터럽트 컨텍스트(인터럽트 핸들러 내부)에서는 절대 사용할 수 없습니다.
### 12.2 바쁜 대기 (Busy-waiting)
- **함수**: `udelay()`, `ndelay()`
- **사용처**: 아주 짧은 지연이 필요할 때 사용하며, 어느 컨텍스트에서든 사용 가능합니다.
### 12.3 다이내믹 타이머의 위치
- **다이내믹 타이머의 핸들러는 인터럽트 핸들러가 실행되는 환경과 동일한 컨텍스트에서 실행됩니다.**
- 따라서 **타이머 핸들러 내부에서는 `msleep()`과 같은 수면 함수를 사용할 수 없습니다.**
