## 1. 주요 학습 내용 (Slide 2)
이 파트에서는 리눅스 커널 프로그래밍에 필수적인 **기본 커널 함수**들을 다룹니다.:
- **사용자 메모리 접근 (User memory access)**
- **동적 메모리 할당 (Dynamic memory allocation)**
- **연결 리스트 (Linked lists)**
- **스핀락 (Spinlock)**
- **지연 함수 (Delay)**

---
## 2. 내보내기 된 커널 함수 (Slide 3-4)
커널 모듈에서 커널의 기능을 사용하기 위해서는 해당 함수나 변수가 **내보내기(Export)** 되어 있어야 합니다.
- **확인 방법:** `/proc/kallsyms` 파일을 통해 현재 내보내기 된 커널 심볼들을 확인할 수 있습니다.
- **내보내기 매크로:** `EXPORT_SYMBOL()` 또는 `EXPORT_SYMBOL_GPL()`을 사용하여 심볼을 공개합니다.
- **심볼 해석 (Symbol Resolve):** 모듈이 적재(insertion)될 때 커널 심볼 테이블을 통해 모듈 내의 커널 참조를 해결합니다.
- **사용 예시:** 지금까지 사용한 `printk()`, `alloc_chrdev_region()`, `cdev_init()`, `cdev_add()` 등은 모두 내보내기 된 함수들입니다.

## 3. 사용자 메모리 접근 (Slide 5-7)
커널은 보안과 안정성을 위해 사용자 공간(User Space)의 메모리에 직접 접근하지 않고 전용 함수를 사용합니다.
### 3.1 블록 데이터 복사 (Slide 5)
- **`copy_to_user(to, from, n)`:** 커널 데이터를 사용자 공간으로 복사합니다.
- **`copy_from_user(to, from, n)`:** 사용자 데이터를 커널 공간으로 복사합니다.
### 3.2 직접 접근을 하지 않는 이유 (Slide 6)
- 사용자 버퍼가 읽기/쓰기가 불가능한 경우 `-EFAULT`를 반환하여 시스템을 보호합니다.
- 포인터가 커널 메모리 주소를 가리키는 보안 문제를 방지합니다.
### 3.3 기타 접근 함수 (Slide 7)
- **`get_user()` / `put_user()`:** `char`, `int`와 같은 단순 변수(단일 값)를 읽거나 쓸 때 사용합니다.
- **`clear_user()`:** 사용자 공간의 메모리 블록을 0으로 채웁니다.
- **`strnlen_user()` / `strncpy_from_user()`:** 사용자 공간의 문자열 크기를 구하거나 복사할 때 사용합니다.

## 4. 메모리 할당 (Slide 8-9)
커널 내에서 동적으로 메모리를 할당하는 방법은 크게 두 가지가 있습니다.
### 4.1 vmalloc (Slide 8)
- **특징:** 가상 주소 공간에서는 연속적이지만, 물리적 메모리에서는 연속적이지 않을 수 있습니다.
- **용도:** 물리적 연속성이 중요하지 않은 큰 순차적 메모리 버퍼를 할당할 때 사용합니다.
- **제한:** DMA(Direct Memory Access)용 메모리 할당에는 적합하지 않습니다.
### 4.2 kmalloc (Slide 9)
- **특징:** 가상 주소와 물리적 메모리 모두에서 **연속적인** 영역을 할당합니다.
- **주요 플래그 (Flags):**
    - **`GFP_KERNEL`:** 일반적인 커널 메모리 할당이며, 메모리가 부족할 경우 할당 프로세스가 잠들 수(sleep) 있습니다.
    - **`GFP_ATOMIC`:** 할당 시 잠들지 않으므로, 인터럽트 핸들러 내부와 같이 즉각적인 할당이 필요한 곳에서 사용합니다.
    - **`GFP_DMA`:** DMA 처리에 적합한 메모리 영역을 할당합니다.
> **💡 핵심 요약** 커널 프로그래밍 시 사용자 메모리는 반드시 `copy_to/from_user` 함수를 통해 안전하게 접근해야 하며 , 메모리 할당 시에는 물리적 연속성이 필요한지(`kmalloc`) 혹은 큰 가상 공간이 필요한지(`vmalloc`)에 따라 적절한 함수를 선택해야 합니다.

## 5. 연결 리스트 (Linked Lists) 개요 (Slide 11)
리눅스 커널은 데이터 관리를 위해 효율적인 **환형 이중 연결 리스트(Circular Doubly Linked List)** 프레임워크를 제공합니다 .
- **구조:** 각 노드는 이전 노드(`prev`)와 다음 노드(`next`)를 가리키는 포인터를 가집니다 .
- **주의사항:** 커널이 제공하는 기본 리스트 함수들은 자체적으로 **잠금(Locking)을 수행하지 않습니다**. 따라서 여러 프로세스가 동시에 리스트에 접근할 경우, 별도의 동기화 처리를 해주어야 합니다 .

---
## 6. 데이터 구조 및 선언 (Slide 12)
### 6.1 `struct list_head`
리스트를 연결하는 고리 역할을 하는 구조체입니다.
C
```
struct list_head {
    struct list_head *next, *prev;
};
```
### 6.2 사용 방법 (Usage)
사용자가 정의한 데이터 구조체 안에 `struct list_head`를 멤버로 포함시켜 사용합니다 .
- 예: `struct my_node { int data; struct list_head list; };`
### 6.3 초기화
리스트의 시작점(Header)은 사용 전에 반드시 초기화해야 합니다.
- `void INIT_LIST_HEAD(struct list_head *list)`

---
## 7. 리스트 요소 추가 및 삭제 (Slide 13-14)
### 7.1 요소 추가 (Add)
- **`list_add(new, head)`:** 지정한 `head` 바로 **뒤**에 새 요소를 삽입합니다 (Stack 방식과 유사) .
- **`list_add_tail(new, head)`:** 지정한 `head` 바로 **앞**(즉, 리스트의 마지막)에 새 요소를 삽입합니다 (Queue 방식과 유사) .
### 7.2 요소 삭제 (Deletion)
- **`list_del(entry)`:** 리스트에서 특정 요소를 제거합니다 .
- **`list_del_init(entry)`:** 리스트에서 요소를 제거한 후, 해당 요소의 포인터를 다시 자기 자신을 가리키도록 재초기화합니다 .

---
## 8. 리스트 순회 (Iteration) (Slide 15-17)
리스트에 담긴 데이터를 하나씩 확인하기 위해 매크로 함수를 사용합니다.
### 8.1 기본 순회
- **`list_for_each(pos, head)`:** 리스트의 모든 `list_head` 요소를 순회합니다 .
    - `pos`: 루프에서 현재 위치를 나타낼 커서 포인터.
    - `head`: 순회를 시작할 리스트의 머리 부분.
### 8.2 데이터 추출: `list_entry` (Slide 16)
`list_head` 주소로부터 실제 데이터 구조체의 시작 주소를 찾아내는 핵심 매크로입니다.
- 사용 예: `entry = list_entry(pos, struct my_node, list);`
### 8.3 안전한 순회: `list_for_each_safe` (Slide 17)
순회 도중에 현재 노드를 **삭제(`list_del`)해야 할 경우** 반드시 사용해야 하는 버전입니다 .
- 다음 노드의 주소를 미리 저장해 두기 때문에, 현재 노드가 삭제되어 포인터가 끊어져도 루프가 깨지지 않고 안전하게 다음으로 넘어갈 수 있습니다 .

## 9. 스핀락 (Spinlock) (Slide 18-19)
커널 내에서 공유 자원에 대한 동시 접근을 막기 위해 사용하는 가장 기본적인 잠금(Lock) 메커니즘입니다.
### 9.1 동작 원리
- **바쁜 대기 (Busy-waiting):** 누군가 이미 락을 보유하고 있다면, 락을 얻을 때까지 CPU가 루프를 돌며 기다립니다.
- **원자성 (Atomicity):** `spin_lock()` 연산은 다른 프로세스가 끼어들 수 없는 원자적 연산으로 수행됩니다.
### 9.2 특징 및 주의사항
- **Sleep 금지:** 스핀락을 보유한 상태에서 프로세스가 잠들면(Sleep) 시스템이 멈출 수(Deadlock) 있으므로 절대 금지됩니다.
- **빠른 해제:** 스핀락은 아주 짧은 시간 동안만 보유해야 효율적입니다.
### 9.3 주요 함수
- `spinlock_t my_lock = SPIN_LOCK_UNLOCKED;` (초기화)
- `spin_lock(&my_lock);` (잠금 시작)
- `spin_unlock(&my_lock);` (잠금 해제)

## 10. 지연 함수 (Delay) (Slide 20-22)
커널이 특정 시간 동안 기다려야 할 때 사용하는 함수들입니다. 대기 방식에 따라 두 종류로 나뉩니다.
### 10.1 바쁜 대기 지연 (Busy-Waiting Delay) (Slide 20)
CPU가 루프를 돌며 시간을 때우는 방식입니다. 아주 짧은 시간(마이크로/밀리초) 동안 기다릴 때 유용합니다.
- **`udelay(usecs)`:** 지정한 마이크로초(µs)만큼 지연합니다.
- **`mdelay(msecs)`:** 지정한 밀리초(ms)만큼 지연합니다.
- **용도:** 하드웨어 초기화 단계 등 아주 짧은 대기가 필요할 때 사용합니다.
### 10.2 수면 대기 지연 (Sleep-Waiting Delay) (Slide 21-22)
현재 실행 중인 프로세스를 잠재우고 다른 작업이 CPU를 쓸 수 있게 양보하는 방식입니다.
- **`msleep(msecs)`:** 지정한 밀리초만큼 프로세스를 잠재웁니다.
    - **주의:** 프로세스 컨텍스트에서만 사용 가능하며, **인터럽트 핸들러 내에서는 사용할 수 없습니다.**
- **`schedule_timeout()`:** 지정한 시간(jiffies 단위)이 지날 때까지 현재 태스크를 휴면 상태로 만듭니다.
- **`wait_event_timeout()`:** 특정 조건이 참이 되거나 타임아웃이 발생할 때까지 잠듭니다.

---
**💡 핵심 요약**
- **스핀락**은 CPU를 점유한 채 기다리는 방식이므로 임계 구역(Critical Section)이 짧을 때 사용하며, 락 보유 시 절대 잠들면 안 됩니다.
- **지연 함수**는 아주 짧은 대기에는 `udelay`를, 긴 대기에는 시스템 자원을 아끼기 위해 `msleep`을 사용합니다. 단, 인터럽트 환경에서는 `msleep` 같은 수면 함수를 쓸 수 없다는 점을 명심해야 합니다.
