## 1. 개요 (Overview) (2p)
- **분산 시스템의 핵심:** 프로세스 간 통신(Interprocess communication)은 모든 분산 시스템의 심장부임.
- **기반 기술:** 통신은 항상 하부 네트워크가 제공하는 저수준 메시지 패싱(Low-level message passing)에 기반함.
- **개발의 난제:** 현재의 컴퓨터 네트워크 통신 시설만 사용하여 대규모 분산 애플리케이션을 개발하는 것은 매우 어려움.
- **널리 쓰이는 4가지 통신 모델:**
    - **RPC (Remote Procedure Call):** 메시지 패싱의 복잡함을 숨기는 것을 목표로 함.
    - **MOM (Message-oriented Middleware):** 고수준 메시지 큐잉 모델을 사용함.
    - **Data streaming:** 다양한 시간 제약 조건하에서 연속적인 메시지 흐름을 지원함.
    - **Multicast:** 데이터 보급을 위한 새롭고 우아한 해결책임.
## 2. 분산 시스템 통신의 기초: 계층 프로토콜 (3p)
- **메시지 기반 통신:** 분산 시스템은 공유 메모리가 없기 때문에 모든 통신은 (저수준) 메시지 송수신에 기반함.
- **통신 프로세스 간의 합의 사항:**
    - 비트의 의미: 0과 1을 신호로 보내기 위해 몇 볼트(volt)를 사용해야 하는가?
    - 메시지의 끝: 수신자가 메시지의 마지막 비트가 무엇인지 어떻게 아는가?
    - 오류 감지: 메시지가 손상되거나 유실되었는지 어떻게 감지하는가?
    - 데이터 표현: 숫자, 문자열 및 기타 데이터 항목의 길이는 얼마이며 어떻게 표현되는가?
- **표준화:** ISO(국제 표준화 기구)는 다양한 수준을 식별하고 표준 이름을 부여하며 각 계층의 역할을 규정한 참조 모델을 개발함.
- **OSI 모델:** 개방형 시스템 간 상호연결(Open System Interconnection) 참조 모델.
## 3. OSI 모델의 특성 (4-5p)
- **현재의 상태:** OSI 모델의 일부로 개발된 프로토콜들은 널리 사용되지 않고 사실상 사장되었으나, 모델 자체는 컴퓨터 네트워크를 이해하는 데 매우 유용함.
- **설계 목적:** 송수신되는 메시지의 형식, 내용, 의미를 규정하는 표준 규칙을 위해 설계됨.
- **프로토콜:** 이러한 규칙들을 공식화한 것을 의미함.
- **두 가지 일반적인 통신 유형:**
    - **연결 지향 프로토콜 (Connection-oriented):** 예시 - 전화.
    - **비연결형 프로토콜 (Connectionless):** 예시 - 편지.
- **OSI 7계층 구조 (그림 4-1):**
    - 7. 응용 계층 (Application)
    - 6. 표현 계층 (Presentation)
    - 5. 세션 계층 (Session)
    - 4. 전송 계층 (Transport)
    - 3. 네트워크 계층 (Network)
    - 2. 데이터 링크 계층 (Data link)
    - 1. 물리 계층 (Physical)
## 4. 메시지 송수신 절차 (6p)
- **송신** 측 절차 **(Sending side):**
    1. 소스 머신의 프로세스가 메시지를 생성함.
    2. 메시지를 해당 머신의 응용 계층으로 전달함.
    3. 응용 계층 소프트웨어가 메시지 앞에 헤더(Header)를 추가함.
    4. 결과 메시지를 하위 계층으로 전달함.
    5. 메시지가 최하단 계층에 도달하면 실제로 메시지를 전송함.
- **수신 측 절차 (Receiving side):**
    1. 수신된 메시지가 위쪽 계층으로 전달됨.
    2. 각 계층은 자신의 헤더를 떼어내고(Strip off) 조사함.
    3. 최종적으로 메시지가 대상 프로세스에 도착함.
- **정보 활용:** n계층 헤더의 정보는 n계층 프로토콜을 위해 사용됨. (데이터 링크 계층은 트레일러(Trailer)를 추가하기도 함)
## 5. 계층 프로토콜의 장점 (7p)
- **독립성:** 각 계층은 자신만의 프로토콜을 가지며, 다른 계층에 영향을 주지 않고 독립적으로 변경될 수 있음.
- **사례** 비유 (두 **회사 간의 통신):**
    - 사장(Boss)들이 명령을 내리고 비서(Secretary)들이 우편 서비스(Postal service)를 통해 서로 통신함.
    - 우편 서비스의 품질이 떨어지자, 두 비서는 사장들을 방해하지 않고 우편 대신 이메일로 통신 방식을 바꾸기로 결정함.
    - 사장들은 비서들에게 영향을 주지 않고 메시지 내용을 바꿀 수 있음.

## 6. OSI 모델: 하위 계층 프로토콜 (8p)
- **물리 계층 (Physical Layer):** 0과 1의 비트 전송 담당. 전기적, 기계적, 신호 인터페이스 표준화(전압, 초당 비트 수, 단방향/양방향 통신 등).
- **데이터 링크 계층 (Data Link Layer):** 비트 수준의 오류 감지 및 수정. 비트들을 프레임(Frame) 단위로 묶고 체크섬(Checksum)을 통해 정확한 수신 확인.
- **네트워크 계층 (Network Layer):** 송신측에서 수신측 머신까지의 최적 경로 선택(Routing). 메시지가 목적지에 도달하기 위해 여러 홉(Router)을 거치며 각 라우터에서 나가는 선로를 결정함.
    - **IP (Internet Protocol):** 각 IP 패킷은 다른 패킷과 독립적으로 목적지까지 라우팅됨.
## 7. OSI 모델: 전송 계층 프로토콜 (9p)
- **역할:** 하부 네트워크를 앱 개발자가 사용할 수 있는 형태로 변환. 패킷 유실 처리 및 신뢰성 있는 연결 제공.
- **특징:** 메시지를 넣으면 손상 없이 보낸 순서대로 나옴.
- **주요 프로토콜:**
    - **TCP:** IP에 몇 가지 기능을 추가한 신뢰성 있는 방식.
    - **UDP:** 비연결형 프로토콜.
- **절차:** 메시지를 전송 가능한 작은 조각(Packet)으로 분할하고 시퀀스 번호(Sequence number) 할당. 헤더에는 전송/수신 여부, 수신 가능 용량, 재전송 필요 정보 등이 포함됨.
## 8. OSI 모델: 상위 계층 프로토콜 (10p)
- **세션 계층 (Session Layer):** 대화 제어(누가 말하고 있는지 추적) 및 동기화 시설 제공. 실제로는 거의 지원되지 않거나 관심 대상이 아님.
- **표현 계층 (Presentation Layer):** 비트의 **의미(Meaning)**에 집중. 이름, 주소, 금액 등의 필드를 가진 레코드를 정의하고 송수신자 간 데이터 형식을 통일하여 서로 다른 내부 표현 방식을 가진 머신 간 통신을 도움.
## 9. OSI 모델: 응용 계층 프로토콜 (11p)
- **초기 목적:** 이메일, 파일 전송, 터미널 에뮬레이션과 같은 표준 네트워크 앱들을 포함하기 위해 고안됨.
- **현재:** 모든 애플리케이션과 프로토콜을 담는 컨테이너 역할을 함.
- **주요 사례:**
    - **FTP (File Transfer Protocol):** 파일 전송을 위한 프로토콜 정의(ftp 프로그램과 혼동 주의).
    - **HTTP (HyperText Transfer Protocol):** 웹 페이지 전송 및 관리를 위해 설계되었으며 웹 브라우저와 서버에서 구현됨.
## 10. 미들웨어 프로토콜 (Middleware Protocols) (12-14p)
- **정의:** 논리적으로 응용 계층에 위치하지만, 특정 앱에 종속되지 않는 범용 프로토콜들을 포함하여 독립적인 계층을 형성하는 소프트웨어.
- **미들웨어 서비스 프로토콜:**
    - **인증 프로토콜 (Authentication):** 특정 앱에 묶이지 않은 일반 서비스로 통합 가능.
    - **인가 프로토콜 (Authorization):** 애플리케이션 독립적인 성격을 가짐.
    - **커밋 프로토콜 (Commit):** 원자성(Atomicity) 지원. 그룹 내 모든 프로세스가 작업을 수행하거나 아무도 수행하지 않음을 보장.
    - **분산 잠금 프로토콜 (Distributed Locking):** 여러 머신에 분산된 프로세스들이 자원에 동시 접근하는 것을 방지.
- **미들웨어 통신 프로토콜:**
    - 고수준 통신 서비스 지원 (예: 원격 machine의 프로시저/객체 호출의 투명성).
    - 실시간 데이터 전송을 위한 스트림 설정 및 동기화.
    - 신뢰성 있는 멀티캐스트 서비스.
    - 다양한 전송 프로토콜을 사용하면서도 단일 인터페이스를 제공함.
## 11. 수정된 참조 모델 (Adapted Reference Model) (15p)
- **계층 통합:** 기존 OSI 모델의 세션 및 표현 계층이 하나의 **미들웨어 계층(Middleware layer)**으로 대체됨.
- **특징:** 미들웨어 계층은 애플리케이션 독립적인 프로토콜들을 포함하며, 하부 전송 프로토콜의 차이를 숨김.
- **수정된 계층 구조 (그림 4-3):**
    1. **6. Application protocol:** 최종 사용자용 서비스 정의.
    2. **5. Middleware protocol:** 범용 서비스(인증, 스트림 동기화 등) 제공.
    3. **4. Transport protocol:** 데이터 전송 제어.
    4. **3. Network protocol:** 패킷 라우팅.
    5. **2. Data link protocol:** 프레임 전송 및 오류 수정.
    6. **1. Physical protocol:** 전기적/기계적 신호 전송.

## 12. 통신의 유형 (Types of Communication) (16-17p)
- **미들웨어의 역할:** 클라이언트-서버 컴퓨팅에서 중간 매개 서비스로 작동함 (예: 이메일 시스템의 코어).
- **통신 유형의 분류:**
    - **Persistent(지속성) vs Transient(일시성)** 통신
    - **Synchronous(동기) vs Asynchronous(비동기)** 통신
    - **Discrete(이산) vs Streaming(스트리밍)** 통신
- **중간 서비스 모델:** 미들웨어는 응용 계층 통신에서 메시지를 임시 저장하고 전달하는 '저장 시설(Storage facility)' 역할을 수행함 (그림 4-4).
## 13. 지속성 vs 일시성 통신 (18p)
- **Persistent Communication (지속성):** 전송된 메시지가 수신자에게 전달될 때까지 미들웨어에 계속 보관됨.
    - **송신자:** 메시지 제출 후 즉시 다른 작업 수행 가능.
    - **수신자:** 메시지가 제출될 당시에 반드시 실행 중일 필요가 없음.
    - **사례:** 이메일 시스템.
- **Transient Communication (일시성):** 송신자와 수신자 애플리케이션이 실행 중인 동안에만 메시지가 유지됨.
    - 미들웨어가 전송 실패 시 메시지를 즉시 폐기(Discard)함.
    - **사례:** 대부분의 전송 계층(Transport-level) 서비스.
## 14. 동기 vs 비동기 통신 (19-20p)
- **Asynchronous Communication (비동기):** 송신자가 메시지를 보낸 직후 바로 다음 코드를 실행함. 메시지는 미들웨어에 의해 임시로 저장됨.
- **Synchronous Communication (동기):** 요청이 수락되거나 처리될 때까지 송신자가 블록(Blocked)됨.
- **3가지 동기화 지점:**
    1. **제출 시 동기화:** 미들웨어가 전송을 책임지겠다고 응답할 때까지 대기.
    2. **배달 시 동기화:** 메시지가 수신자에게 도착할 때까지 대기.
    3. **처리 후 동기화:** 수신자가 요청을 완전히 처리하고 응답을 보낼 때까지 대기 (예: RPC).
- **주요 조합:**
    - **메시지 큐잉 시스템:** 지속성 + 비동기 통신의 대표적 형태.
    - **RPC (원격 프로시저 호출):** 일시성 + 동기 통신의 대표적 형태.
