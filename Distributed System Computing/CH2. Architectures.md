# 분산 시스템 제2장: 아키텍처 (Architectures) 상세 학습 노트
**Subject:** 분산 시스템 및 컴퓨팅 **Scope:** Chapter 2 (Main Slides 1-45 + Extra Materials 1-3) **Goal:** 분산 시스템의 논리적/물리적 구조, 미들웨어 패턴, 최신 클라우드 및 블록체인 아키텍처 완전 정복
## 1. 아키텍처의 기본 개념 (Architectures)
### 1.1 아키텍처의 정의
- **조직(Organization):** 분산 시스템을 구성하는 소프트웨어 컴포넌트들의 배치와 상호작용 방식.
- **소프트웨어 아키텍처 (Software Architecture):** 시스템을 구성하는 소프트웨어 컴포넌트들의 **논리적 조직**.
- **시스템 아키텍처 (System Architecture):** 소프트웨어 아키텍처가 실제 물리적 기기들에 어떻게 배치되는지 결정하는 **최종 인스턴스화(Instantiation)**.
### 1.2 아키텍처의 목적 및 적응성
- **분산 시스템의 목표:** 미들웨어 계층을 통해 애플리케이션을 하부 플랫폼과 분리하고, 사용자에게 **분산 투명성(Distribution Transparency)**을 제공하는 것.
- **적응성(Adaptability):** 시스템이 스스로 자신의 동작을 모니터링하고 필요할 때 적절한 조치를 취하는 능력. 이를 수행하는 시스템을 **자율 시스템(Autonomic systems)**이라 함.
### 1.3 소프트웨어 아키텍처의 구성 요소
- **컴포넌트 (Component):** 잘 정의된 인터페이스를 가진 모듈 단위. 환경 내에서 교체 가능함.
- **커넥터 (Connector):** 컴포넌트 간의 통신, 조정, 협력을 중재하는 메커니즘 (예: RPC, 메시지 패싱, 스트리밍).
- **구성(Configuration):** 컴포넌트와 커넥터가 결합되어 전체 시스템을 이루는 방식.
## 2. 소프트웨어 아키텍처 스타일 (Architectural Styles)
분산 투명성을 목표로 하되 성능, 결함 허용, 프로그래밍 편의성 사이의 **트레이드오프(Trade-offs)**를 고려하여 선택함.
### 2.1 주요 스타일 4가지
1. **계층화 아키텍처 (Layered):**
    - 컴포넌트들이 층층이 쌓인 구조. $L_i$ 계층은 하부 $L_{i-1}$ 계층만 호출 가능(역방향 불가).
    - **요청(Request):** 위에서 아래로, **응답(Response):** 아래에서 위로 흐름.
    - _추가 분류:_ Pure(직후 하위만), Mixed(건너뛰기 허용), Upcalls(하위->상위 신호).
2. **객체 기반 아키텍처 (Object-based):**
    - 객체들이 RPC(원격 프로시저 호출)를 통해 연결됨. 클라이언트-서버 모델과 가장 잘 맞음.
3. **데이터 중심 아키텍처 (Data-centered):**
    - 공통의 수동적/능동적 **리포지토리(Repository)**를 통해 프로세스들이 통신함.
    - 예: 공유 분산 파일 시스템, 웹 기반 시스템.
4. **이벤트 기반 아키텍처 (Event-based):**
    - **발행/구독(Publish/Subscribe)** 시스템. 이벤트 전파를 통해 통신하며 컴포넌트 간 **느슨한 결합(Loosely coupled)**이 장점.
### 2.2 결합 해제(Decoupling) 모델 (Extra)

|구분|시간 결합 (Temporally Coupled)|시간 분리 (Temporally Decoupled)|
|---|---|---|
|**참조 결합 (Referentially Coupled)**|직접 통신 (Direct)|메일박스 (Mailbox)|
|**참조 분리 (Referentially Decoupled)**|이벤트 기반 (Event-based)|**공유 데이터 공간 (Shared Data Space)**|
- **Shared Data Space:** 발행자와 구독자가 동시에 활성화될 필요가 없는 시간적/참조적 완전 분리 상태.
### 2.3 미들웨어 디자인 패턴 (Extra)
- **Wrappers:** 레거시 컴포넌트의 인터페이스를 클라이언트에 맞게 변환해주는 특별한 컴포넌트. **Broker** 미들웨어를 통해 래퍼의 수를 최적화함.
- **Interceptors:** 제어 흐름을 가로채서 다른 코드(예: 복제본 호출)가 실행되게 하는 소프트웨어 컴포넌트.
## 3. 중앙 집중식 아키텍처 (Centralized: Client-Server)
### 3.1 클라이언트-서버 모델
- **서버:** 서비스를 구현하고 제공하는 프로세스.
- **클라이언트:** 서비스를 요청하고 응답을 기다리는 프로세스.
### 3.2 통신 프로토콜
- **비연결성 (UDP):** 효율적이지만 전송 실패 처리가 어려움.
- **멱등성 (Idempotency):** 연산을 여러 번 반복해도 결과가 같은 성질. 재전송 시 중요 (예: 잔액 조회는 멱등적, 이체는 비멱등적).
- **연결 지향 (TCP):** 불안정한 WAN 환경에서 신뢰성이 높으나 연결 설정/해제 비용이 큼.
### 3.3 애플리케이션 계층화 (Application Layering)
1. **User-interface level:** 화면 관리 및 사용자 인터페이스 전담. 주로 클라이언트가 수행.
2. **Processing level:** 핵심 로직. 검색 엔진의 쿼리 생성, 랭킹 알고리즘 등.
3. **Data level:** 실제 데이터 관리 및 일관성 유지. 서버 측에서 관계형 DB 등으로 구현.
### 3.4 다중 계층 배치 (Multi-tiered)
- **(a)~(e) 조직:** 클라이언트가 '얇은지(Thin)' '두꺼운지(Fat)'에 따라 나뉨.
    - (a): 클라이언트엔 단말기 의존적 UI만 존재. 서버가 거의 모든 제어권 가짐.
    - (b): 클라이언트가 전체 UI 담당.
    - (c): 클라이언트에서 폼(Form) 체크 등 일부 로직 수행. (예: Javascript를 이용한 프론트엔드 검증)
    - (d): 클라이언트가 UI와 로직 전체 담당. 서버는 데이터만 관리.
    - (e): 클라이언트가 UI, 로직 전체, 그리고 데이터의 일부(캐시 등)까지 담당.
- **3-tier 모델:** 단일 서버 대신 여러 서버(App 서버, DB 서버 등)가 역할을 나누어 수행. 서버가 때로는 클라이언트로 동작함.
## 4. 탈중앙화 아키텍처 (Decentralized)
### 4.1 분산의 종류
- **수직적 분산 (Vertical):** 논리적으로 다른 계층(UI, 로직, 데이터)을 다른 기기에 배치.
- **수평적 분산 (Horizontal):** 동일한 기능을 물리적으로 쪼개어 부하 분산 (P2P).
### 4.2 Peer-to-Peer (P2P) 시스템
- **오버레이 네트워크 (Overlay Network):** 프로세스 노드와 통신 채널 링크로 이루어진 가상 네트워크.
- **구조화된 P2P (Structured):**
    - **DHT (분산 해시 테이블):** 결정론적 방식으로 데이터 키를 노드 ID에 매핑.
    - **Chord 시스템:** 노드를 링(Ring)으로 연결. 키 $k$는 $id \ge k$인 첫 번째 노드인 **Successor($succ(k)$)**가 담당함.
    - **Join/Leave:** 새로운 노드는 `lookup(id)`로 위치를 찾아 들어가고, 나가는 노드는 데이터를 `succ(id)`에게 넘김.
- **비구조화된 P2P (Unstructured):**
    - 무작위 알고리즘 기반. 데이터 찾을 때 **Flooding(플러딩)** 사용.
    - **슈퍼피어 (Superpeers):** 검색 효율을 위해 인덱스를 관리하는 상위 노드 계층 도입. 일반 피어는 슈퍼피어에 고정되어 통신함.
## 5. 하이브리드 및 최신 트렌드 (Hybrid & Modern)
### 5.1 하이브리드 모델
- **BitTorrent:** 트래커(중앙 인덱스) + 피어 전송(분산). "Tit-for-tat(눈에는 눈 이에는 이)" 전략으로 협업 강제.
### 5.2 클라우드 컴퓨팅 (Cloud Computing)
- **4계층 구조:** Hardware → Infrastructure (가상화) → Platform (개발 환경) → Application.
- **서비스 모델:**
    - **IaaS:** 가상 컴퓨팅/저장소 자원 제공 (Amazon EC2/S3).
    - **PaaS:** 앱 개발/배포 수단 제공 (Google App Engine, MS Azure).
    - **SaaS:** 완성된 소프트웨어 서비스 (Gmail, Google Docs).
### 5.3 에지 및 포그 컴퓨팅 (Edge/Fog)
- **에지 컴퓨팅:** 지연 시간(Latency) 감소와 보안을 위해 네트워크 끝단(사용자 근처)에서 처리.
- **포그 컴퓨팅:** 클라우드와 에지의 경계가 모호해지는 지점.
### 5.4 블록체인 (Blockchain)
- **분산 원장:** 참여자를 신뢰할 수 없다는 가정이 핵심.
- **검증 방식:** 중앙 집중식 / 소수 그룹 분산 / **완전 탈중앙화(Consensus 합의)**.
## 6. 자기 관리 (Self-management)
### 6.1 피드백 제어 모델 (Feedback Control Loop)
시스템이 자신의 실행 동작을 자동으로 적응시키는 모델.
1. **모니터링:** 시스템 행동 측정 (예: 응답 지연 시간).
2. **분석:** 측정값과 기준값(Reference input) 비교. 적응 알고리즘 포함. 루프의 핵심.
3. **동작 영향 (Adjustment):** 실제 보정(Corrections) 수행. (예: 복제본 배치 변경, 요청 재지정 등)
**핵심 용어 및 개념 정리:**
- **Middleware Broker:** 여러 래퍼를 효율적으로 관리하여 통신 비용 절감.
- **Interoperability:** 다른 제조사 부품끼리 공통 표준으로 함께 일하는 능력.
- **Successor:** Chord 링에서 키값보다 크거나 같은 ID를 가진 첫 번째 실제 노드.
- **Idempotent:** 여러 번 실행해도 결과가 변하지 않는 안전한 연산.
