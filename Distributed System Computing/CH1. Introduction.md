# 분산 시스템 제1장: 도입 (Introduction) 상세 학습 노트
**Subject:** 분산 시스템 및 컴퓨팅 **Scope:** Chapter 1 (Main Slides 1-37 + Extra Materials 1-2) **Goal:** 분산 시스템의 정의, 목표(투명성, 개방성, 확장성), 설계 기법 및 최신 분류 체계 이해
## 1. 분산 시스템의 기초 및 정의
### 1.1 기술적 배경
- **1980년대 중반 이후의 변화:** 강력한 마이크로프로세서의 보급과 고속 컴퓨터 네트워크의 발전이 분산 시스템의 탄생을 이끎.
### 1.2 분산 시스템의 정의
- **공식 정의:** 사용자에게는 **하나의 일관된 시스템(Single Coherent System)**처럼 보이지만, 실제로는 **독립된 컴퓨터들의 집합(Collection of independent computers)**인 시스템.
- **핵심 측면:** 구성 요소(컴퓨터)는 자율적(Autonomous)이며, 사용자(사람 또는 프로그램)는 단일 시스템과 상호작용한다고 인식함.
### 1.3 분산 시스템의 특징
- **차이점 은폐:** 다양한 하드웨어 및 통신 방식의 차이가 사용자에게 숨겨짐.
- **일관된 상호작용:** 언제 어디서 접속하든 균일한 방식으로 시스템 이용 가능.
- **확장성:** 독립된 컴퓨터들로 구성되어 확장이 용이함.
- **지속 가용성:** 일부 구성 요소가 고장 나더라도 시스템은 전체적으로 계속 작동함.
## 2. 미들웨어 (Middleware)
- **논리적 위치:** 상위 애플리케이션/사용자 계층과 하부 운영체제(OS)/통신 시설 계층 사이에 위치하는 소프트웨어 레이어.
- **역할:** 하드웨어 및 운영체제의 차이를 각 애플리케이션으로부터 최대한 숨겨서 서로 다른 애플리케이션들이 원활하게 통신하도록 돕는 '접착제' 역할.
- **구조:** 서로 다른 로컬 OS 위에서 공통된 인터페이스를 제공하여 애플리케이션 분산 배치를 가능케 함.
## 3. 분산 시스템의 4대 목표
### 3.1 자원 접근성 (Making Resources Accessible)
- **목표:** 원격 자원(프린터, 데이터베이스, 문서 등)을 효율적이고 통제된 방식으로 공유함.
- **가상 조직 (Virtual Organizations):** 지리적으로 멀리 떨어진 사람들이 그룹웨어(Groupware)를 통해 협업하는 형태.
- **주의사항:** 공유와 연결성이 증가할수록 **보안(Security)**의 중요성이 비약적으로 커짐.
### 3.2 분산 투명성 (Distribution Transparency)
- **정의:** 시스템이 분산되어 있다는 사실을 사용자에게 숨겨 단일 컴퓨터처럼 보이게 함.
- **투명성 종류 (8가지):**
    - **Access:** 데이터 표현 방식 및 자원 접근 방식의 차이 은폐 (예: 서로 다른 OS의 파일 명명 규칙).
    - **Location:** 자원의 물리적 위치 은폐 (예: URL).
    - **Migration:** 자원이 이동해도 접근 방식이 바뀌지 않게 숨김.
    - **Relocation:** **사용 중**에 자원이 이동해도 끊김 없이 유지 (예: 모바일 사용자 이동).
    - **Replication:** 자원이 여러 개 복제되어 있다는 사실을 숨김.
    - **Concurrency:** 여러 사용자가 동시에 공유 자원을 써도 서로 방해받지 않게 함 (Locking 메커니즘 활용).
    - **Failure:** 자원의 장애 발생 및 복구 과정을 사용자 모르게 처리함.
- **투명성의 정도(Degree):** 100% 투명성은 불가능하거나 비효율적임. (예: 빛의 속도 한계로 인한 물리적 지연, 성능 저하 방지를 위한 장애 노출 등). 성능과 투명성 사이의 **트레이드오프** 결정이 중요.
### 3.3 개방성 (Openness)
- **정의:** 표준 규칙(Syntax & Semantics)에 따라 서비스를 제공하는 시스템.
- **IDL (Interface Definition Language):** 서비스의 구문(함수명, 파라미터 등)을 정의하는 언어.
- **핵심 지표:**
    - **Interoperability (상호운용성):** 서로 다른 제조사 시스템이 공통 표준에 의존하여 함께 작동하는 능력.
    - **Portability (이식성):** 한 시스템의 앱을 수정 없이 다른 시스템에서 실행할 수 있는 능력.
- **설계 원칙:** 정책(Policy)과 메커니즘(Mechanism)을 분리하여 유연성을 확보해야 함.
### 3.4 확장성 (Scalability)
- **3대 차원:** Size(사용자/자원 추가), Geographical(지리적 거리), Administrative(관리 도메인 확장).
- **확장성 저해 요인:** 중앙 집중식 서비스, 데이터, 알고리즘 (병목 현상의 원인).
- **분산 알고리즘 특징:** 전체 정보 없음, 로컬 정보로 결정, 한 대 고장 나도 작동, 글로벌 클록 가용 안 함.
## 4. 확장 기법 (Scaling Techniques)
- **통신 지연 숨기기:** 비동기 통신(Asynchronous) 사용, 계산 로직을 클라이언트로 이동(Shipping code, 예: Javascript 폼 체크)하여 통신 횟수 단축.
- **분산 (Distribution):** 컴포넌트를 쪼개서 뿌림. (예: DNS 네임스페이스의 계층적 Zone 분할).
- **복제 및 캐싱 (Replication & Caching):** 복사본을 가까이 두어 가용성 증대 및 부하 분산.
    - **일관성 문제:** 복사본이 많아지면 데이터가 꼬일 수 있어 글로벌 동기화 메커니즘 필요.
## 5. 설계 시 함정 (Pitfalls) 및 유형
### 5.1 개발자가 하는 8가지 잘못된 가정
- 네트워크는 신뢰할 수 있다 / 안전하다 / 동질적이다 / 위상은 변하지 않는다 / 지연 시간은 0이다 / 대역폭은 무한하다 / 전송 비용은 0이다 / 관리자는 한 명뿐이다.
### 5.2 분산 시스템의 유형
- **Computing systems:** 고성능 연산용 (Cluster, Grid).
- **Information systems:** 조직 내 서버-클라이언트 앱 중심.
- **Pervasive systems:** 모바일, 임베디드 장치 등 불안정성이 기본인 환경.
## 6. 추가 자료 심화 내용 (Extra Materials)
### 6.1 구조적 특성
- **Decentralized:** 자원이 필연적으로(necessarily) 흩어짐.
- **Distributed:** 자원을 전략적으로 충분히(sufficiently) 흩어놓음.
### 6.2 신뢰성 (Dependability) 4요소
- **Availability (가용성):** 특정 시점에 사용 가능할 확률.
- **Reliability (신뢰도):** 특정 기간 동안 고장 없을 확률.
- **Safety (안전성):** 고장 시에도 치명적 피해 없음.
- **Maintainability (유지보수성):** 수리가 용이함.
### 6.3 고장 체인 (Fault Chain)
- **Fault (결함/원인, 버그) → Error (오류/상태, 잘못된 값) → Failure (장애/결과, 기능 정지).**
### 6.4 계층별 특징 (Cloud vs Edge vs IoT)
- **Cloud (상위):** 높은 계산력/저장공간, 안정적 연결, 높은 지연 시간(Latency).
- **IoT (하위):** 낮은 지연 시간, 높은 위치/상황 인지력, 수많은 기기, 이동성 지원.
- **Edge:** 클라우드와 IoT 사이에서 응답성을 확보하는 완충 지대.
